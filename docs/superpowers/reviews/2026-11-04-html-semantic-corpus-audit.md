# Semantic corpus and documentation HTML audit

Every changed semantic case and example is listed below. This review distinguishes
actual generated HTML from GSX syntax layout. Before this correction, existing
corpus input sources were unchanged except the whitespace-only children rejection addition; most apparent
indentation changes came from emitting existing literal HTML text.

The runtime and documentation generator do not pretty-print or dedent output.
Ordinary fixtures now author the desired HTML indentation explicitly: a root at
column zero, child content one level deeper, and a matching closing tag. Setup
Go blocks are adjacent to following output where an incidental blank line was
not part of the regression. Tight scalar examples remain compact. Deliberate
whitespace, raw text, escaping, security and serialization cases retain their
byte contracts. Goldens were regenerated through the canonical harness.

All 184 migrated files were checked for identical non-whitespace scanner tokens
and identical string-literal token values. The only structural exceptions are
removal of unnecessary fragments in the two ordinary signature examples; those
examples test component signatures, not fragment whitespace. Regenerated render
sections were read individually. No JS/CSS body or multiline Go/raw literal was
reindented by the source migration.

The two ordinary unit fixtures were also corrected at their source: spread-fold
setup blocks touch the element and direct-render return blocks touch the closing
tag. Their original strict HTML expectations and write-boundary checks remain.
